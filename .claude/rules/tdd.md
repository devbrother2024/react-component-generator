> **이 규칙은 Rigid다.** 상황에 맞게 완화하거나 "이번엔 예외"로 변형하지 마라. 예외가 필요하다고 느껴지는 순간이야말로 이 문서를 다시 읽어야 하는 순간이다.

# TDD Rule

## 0. 우선순위 — 이 파일은 기본값(fallback)이다

프로젝트 루트의 `CLAUDE.md` 또는 `AGENTS.md`에 TDD 관련 규칙이 명시되어 있다면 **그 규칙이 이 문서보다 우선**한다. 이 파일은 프로젝트별 규칙이 없을 때 적용되는 기본 규칙일 뿐이다. 충돌하면 프로젝트 문서를 따르고, 이 문서는 무시한다.

## 1. 적용 기준

### TDD를 반드시 적용해야 하는 대상
- **비즈니스 로직** — 도메인 규칙, 계산, 상태 전이
- **API 엔드포인트/핸들러** — 요청 검증, 응답 형식, 에러 케이스
- **유틸리티 함수** — 순수 함수든 아니든, 입출력이 명확한 로직
- **버그 수정** — 반드시 그 버그를 재현하는 테스트를 먼저 작성

### TDD가 불필요한 대상
- **타입 정의** (interface, type alias 등) — 검증할 "동작"이 없음
- **설정 파일** (config, env schema 등) — 선언적이며 실행 로직이 없음
- **순수 UI** (마크업/스타일만 있는 프레젠테이셔널 컴포넌트) — 시각적 결과는 테스트보다 리뷰/스냅샷이 적합
- **SQL** (마이그레이션, 순수 쿼리 정의) — 별도 마이그레이션 검증 절차를 따름

판단이 애매하면 "이 코드가 실행됐을 때 관찰 가능한 동작(output, side effect, 상태 변화)이 있는가"를 기준으로 삼는다. 있으면 TDD 대상이다.

## 2. RED → GREEN → REFACTOR 사이클

### RED
- **하나의 동작 = 하나의 테스트.** 여러 동작을 한 테스트에 몰아넣지 않는다.
- 테스트를 작성한 뒤 **반드시 실행해서 실패를 직접 확인**한다. 실행하지 않고 "당연히 실패할 것"이라 가정하지 않는다.
- 실패 이유가 **"기능이 아직 구현되지 않았기 때문"**이어야 한다. 문법 오류, import 누락, 오타 때문에 실패한 것이라면 RED가 아니다 — 테스트 코드를 고치고 다시 확인한다.

### GREEN
- 테스트를 통과시키는 데 필요한 **최소한의 코드만** 작성한다.
- **YAGNI** — 지금 테스트가 요구하지 않는 기능, 파라미터, 분기를 미리 만들지 않는다.
- 구현 후 **신규 테스트와 기존 테스트 전체가 통과**하는지 실행해서 확인한다. "될 것 같다"로 넘어가지 않는다.

### REFACTOR
- 중복 제거, 이름 개선, 헬퍼 추출 등 **구조 개선만** 한다.
- 전 과정에서 **테스트는 계속 green이어야** 한다. 한 스텝이라도 깨지면 되돌린다.
- **이 단계에서 새 동작을 추가하지 않는다.** 새 동작이 필요하다고 느껴지면 다음 RED로 넘긴다.

### 반복
REFACTOR가 끝나면 다음 동작에 대한 RED로 돌아간다. 한 사이클이 완결되기 전에 여러 동작을 동시에 진행하지 않는다.

## 3. 삭제 강제 규칙

- 테스트보다 프로덕션 코드를 먼저 작성한 것을 발견하면, **그 코드를 삭제하고 RED부터 다시 시작**한다.
- "일단 참고용으로 주석 처리해서 남겨둔다" 같은 우회도 금지한다. 남겨두면 그 코드가 테스트 없이 다음 커밋에 슬쩍 살아남는다. **완전히 삭제**한다.

## 4. 변명 차단표

아래 변명이 떠오르면, 코드를 계속 쓰기 전에 이 표를 먼저 읽는다.

| 변명 | 반론 |
|---|---|
| "너무 단순해서 테스트 불필요" | 단순한 로직이 가장 자주, 가장 조용히 깨진다. 테스트 작성 비용도 그만큼 낮으니 안 쓸 이유가 없다. |
| "나중에 추가하겠다" | "나중"은 오지 않는다. GREEN 이후 컨텍스트는 사라지고, 테스트 없는 코드는 그대로 남는다. |
| "시간이 없다" | 테스트 없이 짠 코드의 디버깅 시간이 테스트 작성 시간보다 항상 더 든다. 지금 아끼는 시간은 나중에 이자가 붙어 돌아온다. |
| "삭제하면 낭비" | 테스트 없이 쓴 코드는 검증된 적이 없다. 낭비되는 건 "검증되지 않은 코드"를 유지보수 대상으로 남기는 것이다. |
| "프로토타입이다" | 프로토타입은 살아남아 프로덕션이 되는 경우가 더 많다. 그 순간 테스트가 없는 코드가 기준이 된다. |
