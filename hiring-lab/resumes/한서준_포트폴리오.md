# 한서준 · 결제·정산 백엔드 포트폴리오

강의 실습용 가상 지원 서류입니다. 기준 시점은 2026년 10월입니다.

## 정산 배치에서 실패한 부분만 다시 처리하기

스텝페이 정산플랫폼팀에서 2023년 2월부터 7월까지 맡은 작업입니다. 가맹점별 수수료 계산 때 같은 요율을 반복 조회하는 구간이 전체 배치 시간의 62%를 차지했습니다. 요율을 시작 시 한 번 읽고, 가맹점 단위 500건 청크를 병렬 처리하도록 바꿨습니다.

한 번에 처리하는 양을 무작정 늘리기보다 실패한 청크의 체크포인트를 남기는 쪽을 택했습니다. 지급이 끝난 가맹점을 다시 계산하지 않도록 처리 상태를 구분했습니다. 복구 절차와 재처리 범위는 운영 담당자와 문서로 확인했습니다.

- 비교 기준: 일 거래 45만 건, 운영 피크일의 배치 실행 시간
- 변경 전후: 4시간 10분 → 38분
- 담당 범위: 배치 처리 구조와 재처리 설계·구현. 지급 승인 정책은 담당 조직이 결정했습니다.

## 결제 재시도와 메시지 발행

2023년 9월부터 2024년 3월까지 중복 결제 방지를 맡았습니다. 요청의 멱등 키와 승인 결과의 Outbox 기록을 함께 사용했습니다. Kafka와 SQS FIFO를 비교했지만 당시 초당 수백 건 규모에서는 Kafka 운영 부담이 컸습니다. SQS FIFO의 순서 보장은 가맹점별 메시지 그룹 안에서 적용했습니다.

도입 후 6개월 중복 승인 0건을 관찰했습니다. 이 결과는 해당 관찰 기간의 승인 기록이며, 모든 장애 상황에서 중복이 발생하지 않는다는 보장은 아닙니다.

## 공개 자료 범위

회사 소스와 거래 데이터는 첨부하지 않았습니다. 이 문서는 이력서에 적은 두 작업의 선택 이유와 제 담당 범위를 보충합니다.
