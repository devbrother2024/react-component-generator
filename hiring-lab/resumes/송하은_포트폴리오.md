# 송하은 · 고객 상담 서비스 백엔드 작업 기록

강의 실습용 가상 지원 서류입니다. 기준 시점은 2026년 10월입니다.

## 문의 분류와 라우팅을 분리한 이유

지니큐에서 2025년 4월부터 9월까지 고객 상담 문의 자동 분류를 맡았습니다. LLM에는 문의를 12개 유형 중 하나로 분류하는 판단만 맡겼습니다. 담당 큐로 보내는 규칙과 SLA 계산은 Python 코드로 고정했습니다.

모델 응답이 JSON 스키마를 통과하지 못하면 한 번만 다시 요청하고, 신뢰도가 낮은 응답은 상담원 검토 큐로 보냈습니다. 상담원이 붙인 정답 1,200건과 비교한 일치율은 87%였습니다. 수동 분류의 기존 정확도를 재지 않아 모델이 사람보다 정확하다고 주장하지 않습니다.

도입 전후 각 4주를 비교했을 때 첫 응답 시간 평균은 3시간 10분에서 1시간 40분으로 줄었습니다. 라우팅 자동화까지 포함한 결과입니다.

## 중복 예약과 조회 속도

도토리헬스에서 예약 API를 만들 때 같은 시간대의 중복 예약을 DB 유니크 제약과 트랜잭션으로 막았습니다. 예약 목록의 N+1 조회도 고쳤습니다. 조회 시간 1.2초 → 180ms는 예약 데이터 20만 건을 둔 로컬 부하 테스트 결과이며 운영 지연 시간으로 소개하지 않습니다.

## 장애 대응에서 남긴 것

지니큐의 알림 웹훅 유실은 타임아웃 3초와 재시도 부재가 원인이었습니다. 우선 누락 건을 다시 보낸 뒤 지수 백오프·최대 5회 재시도와 최종 실패 알림을 추가했습니다. 조치 이유를 트러블슈팅 글과 팀 공유회에 정리했습니다.

운영팀 업무 기간과 교육 기간은 개발 경력에 합산하지 않습니다. 재직 기간은 이력서의 경력 표를 기준으로 확인해 주세요.
